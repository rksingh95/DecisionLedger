```
PRODUCT: Decision Authority Infrastructure (DAI) SDK
VERSION: 0.1.0 (Phase 0 — open source, MIT licence)
LANGUAGE: Python 3.11+
PACKAGE NAME: dai-sdk (import as `dai`)

WHAT THIS PRODUCT IS:
An append-only, cryptographically hash-chained decision ledger SDK for
organisations deploying AI agents in regulated environments. It records
every consequential decision an AI agent makes — what was decided, under
what policy version, with what authority, with what evidence, and whether
any human override occurred — in a structured, immutable, tamper-evident
record. Target compliance: EU AI Act Article 19 logging requirements.

CORE DESIGN PRINCIPLES (never violate these):
1. Append-only. Records are never mutated after commit. No UPDATE. No DELETE.
2. Hash-chained. Each record's integrity hash = SHA-256(previous_hash + canonical_json(record)).
3. Typed. Every field is a typed enum or primitive. No free-text fields in core schema.
4. Non-blocking. SDK failure must never crash the agent. Default: log and continue.
5. Framework-agnostic. Works with bare Python, LangChain, CrewAI, any agent framework.
6. Self-hostable. Entire stack runs via docker compose up. No mandatory cloud dependency.
7. EU AI Act compliant by design. Schema covers Article 19 logging fields explicitly.
```

## PROMPT 03 — Hash chain engine (hash_chain.py)
## ═══════════════════════════════════════════════════

**Session goal:** Build the cryptographic core. This is the tamper-evidence mechanism.

```
[PASTE GLOBAL CONTEXT ABOVE FIRST]

TASK: Build dai/hash_chain.py — the SHA-256 hash chaining engine.

Requirements:

1. CONSTANTS:
   GENESIS_HASH = "0" * 64
   HASH_ALGORITHM = "sha256"

2. FUNCTION: compute_record_hash(previous_hash: str, record: DecisionRecord) -> str
   Algorithm:
   - Get canonical JSON from record.to_canonical_json()
   - Payload = f"{previous_hash}:{canonical_json}".encode("utf-8")
   - Return hashlib.sha256(payload).hexdigest()
   
   Validation:
   - previous_hash must be exactly 64 hex characters
   - Raise HashChainError if not
   
   This function must be DETERMINISTIC across:
   - Python versions (3.11+)
   - Operating systems  
   - Multiple calls with same input
   Write a note in the docstring about what could break determinism
   and how this implementation prevents it.

3. FUNCTION: verify_record(record: DecisionRecord, previous_hash: str) -> bool
   Recomputes expected hash and compares to record.record_hash.
   Returns True if match, False if tampered.

4. FUNCTION: verify_chain(records: list[DecisionRecord]) -> ChainVerifyResult
   Algorithm:
   - Start with GENESIS_HASH
   - For each record in order (by decision_timestamp):
     - Recompute expected hash
     - If mismatch: return ChainVerifyResult(valid=False, broken_at=record.decision_id)
     - Advance previous_hash = record.record_hash
   - Return ChainVerifyResult(valid=True, total_records=len(records))
   
   Edge cases:
   - Empty list: return valid=True, total_records=0
   - Single record: verify against GENESIS_HASH
   - Records must be sorted by decision_timestamp before verification
     (sort internally, do not mutate input)

5. FUNCTION: prepare_record_for_commit(
       create_request: DecisionRecordCreate,
       previous_hash: str,
   ) -> DecisionRecord
   Creates a full DecisionRecord from a create request by:
   - Generating decision_id (UUIDv7 via uuid6)
   - Setting ledger_version = LEDGER_VERSION
   - Setting decision_timestamp = now(UTC) if not provided
   - Setting commit_timestamp = now(UTC)
   - Computing record_hash via compute_record_hash()
   - Setting previous_hash
   Returns fully populated DecisionRecord (frozen, immutable).

6. CLASS: HashChainError(DAIException)
   Raised when hash chain operations fail.
   Include: expected_hash, actual_hash, decision_id in exception data.

Write thorough docstrings. Include example in module docstring showing
a two-record chain being constructed and verified.
Write tests in tests/unit/test_hash_chain.py covering:
- Genesis record hash computation
- Two-record chain: construct and verify
- Tamper detection: modify a field, verify chain breaks
- Empty chain verification
- Single record verification
- Determinism test: same input produces same hash 1000 times
```

```
[PASTE GLOBAL CONTEXT ABOVE FIRST]

TASK: Build dai/context_manager.py and dai/decorators.py.

=== context_manager.py ===

Extend the Decision class with __aenter__ and __aexit__ support so it
can be used as:

    async with Decision.begin(...) as d:
        d.with_policy(...)
        d.with_authority(...)
        result = await agent_do_thing()
        d.with_outcome(outcome=result.label, confidence=result.score)
    # auto-commits on exit

    # Also support sync usage:
    with Decision.begin_sync(...) as d:
        ...
    # auto-commits on exit using commit_sync()

__aexit__ behaviour:
- If no exception: call await self.commit() normally
- If exception raised in body AND with_outcome() was not called:
  - Automatically call self.with_exception(
        exception_type=ExceptionType.conservative_fallback,
        reason_code="unhandled_exception",
    )
  - Set outcome="escalated", confidence=0.0
  - Commit with these values
```
